---
title: Environment Variables
description: Every variable the app reads, and where to get it.
---

Copy `.env.example` to `.env` and fill these in.

| Variable | Purpose |
|---|---|
| `GOOGLE_CLIENT_ID` | Google OAuth client ID — powers both the server OAuth flow and the Google One Tap prompt (read at request time, so a runtime var/secret works without rebuilding — see [Authentication](/docs/authentication)) |
| `GOOGLE_CLIENT_SECRET` | Google OAuth client secret |
| `BETTER_AUTH_SECRET` | Auth encryption secret — generate with `openssl rand -base64 32` |
| `BETTER_AUTH_URL` | App base URL used by better-auth (e.g. `http://localhost:3000`) |
| `NEXT_PUBLIC_APP_URL` | Public base URL, used as a fallback for `BETTER_AUTH_URL` |
| `TURSO_DATABASE_URL` | Turso (libSQL) database URL for local/dev database access |
| `TURSO_AUTH_TOKEN` | Turso auth token |
| `AUTH_RESEND_KEY` | [Resend](https://resend.com/api-keys) API key used to send magic-link sign-in emails |

## Google OAuth credentials

Get `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` from the
[Google Cloud Console](https://console.cloud.google.com/apis/credentials).

Add these as authorized redirect URIs on the OAuth client:

- Local: `http://localhost:3000/api/auth/callback/google`
- Production: `https://rights.institute/api/auth/callback/google`

For Google One Tap, also add your local and production origins (e.g.
`http://localhost:3000`, `https://rights.institute`) as **Authorized
JavaScript origins** — One Tap validates the origin the prompt is served
from, separately from the OAuth redirect URIs.

## Setting these on Cloudflare

The deployed Worker does not read your local `.env`. Set each value as a
Worker secret (or as a var in the Cloudflare dashboard) and redeploy:

```bash
wrangler secret put BETTER_AUTH_SECRET
wrangler secret put TURSO_DATABASE_URL
wrangler secret put TURSO_AUTH_TOKEN
wrangler secret put GOOGLE_CLIENT_ID
wrangler secret put GOOGLE_CLIENT_SECRET
wrangler secret put AUTH_RESEND_KEY
```

Everything is read per request through `lib/env.ts`'s `getEnv()` — the
Cloudflare runtime `env` first, then `process.env` — so a rotated secret
takes effect without a rebuild.

## Checking what the deployment actually sees

`GET /api/health` reports which configuration groups the running instance
can read (presence only, never values):

```bash
curl -s https://rights.institute/api/health
```

```json
{
  "status": "degraded",
  "config": { "auth": false, "database": false, "google": false, "magicLinkEmail": false },
  "missing": ["BETTER_AUTH_SECRET", "TURSO_DATABASE_URL"]
}
```

A `degraded` status is the first thing to check when `/api/auth/get-session`
misbehaves or the browser console warns `GOOGLE_CLIENT_ID is not set` — see
[Authentication](/docs/authentication) for what each missing var disables.

<Callout type="warn">
  `TURSO_DATABASE_URL` is required, including in local dev. The app uses the
  libSQL **web** client (the only one that runs on Cloudflare Workers), which
  supports `libsql:`/`https:`/`wss:` URLs only — there is no local `file:`
  database fallback.
</Callout>
