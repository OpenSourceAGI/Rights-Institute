## Quick start

```bash
# Install dependencies
bun install

# Copy environment config
cp .env.example .env
# Fill in GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, BETTER_AUTH_SECRET, etc.
# See /docs/environment-variables for what each one does.

# Database migrations
bun run db:generate
bun run db:push

# Development
bun run dev          # Vite dev server (Next.js App Router on Cloudflare) → http://localhost:9000
```

## Production build & deploy

```bash
bun run build
bun run deploy
```

The app is built with [vinext](https://www.npmjs.com/package/vinext), which
runs the Next.js App Router on top of Vite and deploys to Cloudflare Workers
via `@cloudflare/vite-plugin`. There is no separate Next.js build step —
`vite.config.ts` is the single source of truth for the build pipeline.

## Database

The app uses [Drizzle ORM](https://orm.drizzle.team) against a
[Turso](https://turso.tech) (libSQL) database in development and Cloudflare
D1 in production.

```bash
bun run db:generate   # generate a new migration from schema changes
bun run db:push       # push the schema straight to the database
bun run db:studio     # open Drizzle Studio
```

Schema lives in `packages/db/src/schema.ts`, migrations in `packages/db/drizzle/`.

## Repository layout

The repo is a pnpm workspace. `app/` holds App Router routes and API
handlers, `lib/` holds the little that is genuinely app-level (the Fumadocs
source loader), and every feature — UI primitives, animations, auth, the
database, and each document or tool — is a package under `packages/`:

```
packages/
  ui/  animations/  text-effects/  site-shell/
  auth/  db/  env/
  cause/  credit/  contract-builder/  investor-rank/
  innovation-timeline/  prosper-license/  prosper-coin/
  startup-tools/  terms-privacy/
```

Import them as `@rights/<name>` where the package has a single public entry
(`import { auth } from '@rights/auth'`), or by subpath where it does not
(`import { Button } from '@rights/ui/button'`). Packages ship TypeScript —
Vite compiles their source with the app, so there is no per-package build
step. `@rights/*` resolves via aliases in `workspace-aliases.ts`, shared by
`vite.config.ts`, `vitest.config.ts`, and `tsconfig.json`.

`packages/README.md` lists what each package holds and how to add a new one.

## Docs site

This documentation is built with [Fumadocs](https://fumadocs.dev) and lives
at `/docs`, sourced from Markdown/MDX files in `content/docs/`. To add a
page, drop an `.mdx` file into `content/docs/` (or `content/docs/pages/` for
a page walkthrough) and list it in the nearest `meta.json`.
