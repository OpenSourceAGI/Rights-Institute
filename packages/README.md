# Workspace packages

Each feature of rights.institute lives in its own package here, so a page in
`app/` is mostly routing and layout: it imports the feature and renders it.
`app/` keeps the App Router routes, `lib/` keeps the two things that are
genuinely app-level (the Fumadocs source loader), and everything else — UI
primitives, animations, auth, the database, and each document or tool — is a
package.

| Package | What it holds |
|---|---|
| [`@rights/animations`](./animations) | Canvas/WebGL backgrounds: Game of Life, globe, quantum geometry, spiral |
| [`@rights/auth`](./auth) | better-auth server instance, browser client, request-time config checks, sign-in components |
| [`@rights/cause`](./cause) | The CAUSE document — 10 Understandings, 10 Rights, 10 Problems |
| [`@rights/contract-builder`](./contract-builder) | Contractor, employment, and co-founder agreement builders with live preview |
| [`@rights/credit`](./credit) | CREDIT, the contribution-accounting model |
| [`@rights/db`](./db) | Drizzle schema, the libSQL/Turso client, and the migrations |
| [`@rights/env`](./env) | `getEnv()` — Worker runtime env first, `process.env` second |
| [`@rights/innovation-timeline`](./innovation-timeline) | Interactive timeline of innovation milestones |
| [`@rights/investor-rank`](./investor-rank) | VC dataset, its transform layer, and the searchable card/table views |
| [`@rights/prosper-coin`](./prosper-coin) | Solidity contracts for the PROSPER token and revenue sharing |
| [`@rights/prosper-license`](./prosper-license) | PROSPER license types, customization, data loader, sample data, rendered page |
| [`@rights/site-shell`](./site-shell) | Site chrome: top nav, hero banner, footer, document nav, docs MDX components |
| [`@rights/startup-tools`](./startup-tools) | Categorized directory of startup tools |
| [`@rights/terms-privacy`](./terms-privacy) | Terms of service and privacy policy |
| [`@rights/text-effects`](./text-effects) | Animated text and card treatments |
| [`@rights/ui`](./ui) | shadcn/ui primitives and the `cn()` class merger |

## Importing

Packages ship TypeScript — there is no per-package build step, and Vite
compiles their source along with the app's. Two import shapes exist, and each
package's `exports` says which it offers:

```ts
import { auth } from '@rights/auth';                 // barrel: one public entry
import { Button } from '@rights/ui/button';          // subpath: one file
```

Packages whose entry points are heavy or mutually independent — `@rights/ui`,
`@rights/animations`, `@rights/text-effects`, `@rights/site-shell`,
`@rights/contract-builder`, `@rights/prosper-license` — are **subpath-only**
on purpose: a barrel would pull all 46 shadcn primitives (or gsap, or cobe,
or framer-motion) into any page that wanted one of them.

`@rights/*` resolves to package source through aliases generated by
[`workspace-aliases.ts`](../workspace-aliases.ts), which `vite.config.ts`,
`vitest.config.ts`, and `tsconfig.json` all share. pnpm's workspace links
would resolve them too; the aliases just make the bundler, the test runner,
the editor, and `tsc` agree on the same files.

## Adding a package

1. `mkdir -p packages/<name>/src` and write the code.
2. Add a `package.json` modelled on a sibling: `@rights/<name>`, `private`,
   `"type": "module"`, an `exports` map, its own dependencies (use
   `workspace:*` for other `@rights/*` packages), and `react`/`react-dom`
   under `peerDependencies` if it renders.
3. Add the name to `WORKSPACE_PACKAGES` in `workspace-aliases.ts`, and the
   matching `paths` entries in `tsconfig.json`.
4. Add `"@rights/<name>": "workspace:*"` to the root `package.json` if `app/`
   imports it, then `pnpm install`.
